# Selectivity와 Clustering Factor 정리

## 1. Selectivity란?

Selectivity는 조건절이 얼마나 적은 데이터를 선택하는지를 의미한다.

즉, 조건으로 데이터를 많이 걸러낼수록 Selectivity가 좋다고 표현한다.

## 2. Selectivity 예시

회원 테이블이 100만 건 있다고 가정한다.

### Selectivity가 좋은 경우

```sql
WHERE member_id = 'A123456'
```

- 1건 조회
- 매우 적은 데이터 조회
- 인덱스 효율 좋음

결론: Selectivity 좋음

### Selectivity가 나쁜 경우

```sql
WHERE gender = 'M'
```

- 50만 건 조회 가능
- 많은 데이터 조회
- 인덱스를 타더라도 테이블 접근 비용이 커질 수 있음

결론: Selectivity 나쁨

## 3. Selectivity 특징

| 조건 | Selectivity |
|---|---|
| PK 조회 | 매우 좋음 |
| 주민번호 | 좋음 |
| 이메일 | 좋음 |
| 성별 | 나쁨 |
| Y/N 상태값 | 나쁨 |
| 상태코드 | 보통 또는 나쁨 |

## 4. 옵티마이저 관점에서 Selectivity

옵티마이저는 조건절을 보고 다음을 판단한다.

```text
조건으로 얼마나 적은 데이터를 조회하는가?
```

조회 건수가 적으면 인덱스 사용 가능성이 높아진다.

조회 건수가 많으면 Full Table Scan을 선택할 가능성이 높아진다.

## 5. Clustering Factor란?

Clustering Factor는 인덱스 순서와 실제 테이블 저장 순서가 얼마나 비슷한지를 의미한다.

쉽게 말하면 인덱스로 찾은 데이터가 테이블에 얼마나 잘 모여 있는지를 나타내는 값이다.

## 6. Clustering Factor가 좋은 상태

테이블 저장 순서가 다음과 같다고 가정한다.

```text
1
2
3
4
5
```

인덱스 순서도 다음과 같다.

```text
1
2
3
4
5
```

이 경우 인덱스를 읽으면 테이블도 거의 순차적으로 접근할 수 있다.

- 디스크 접근 효율 좋음
- 랜덤 액세스 적음
- Clustering Factor 낮음
- 인덱스 효율 좋음

결론: Clustering Factor가 좋다.

## 7. Clustering Factor가 나쁜 상태

테이블 저장 순서가 다음과 같다고 가정한다.

```text
1
500
3
700
20
```

인덱스는 정렬되어 있지만 실제 테이블 데이터 위치는 뒤섞여 있다.

이 경우 인덱스를 따라가면 테이블 블록을 여기저기 이동하면서 읽어야 한다.

- 랜덤 액세스 증가
- 디스크 I/O 증가 가능
- Clustering Factor 높음
- 인덱스 효율 저하

결론: Clustering Factor가 나쁘다.

## 8. 랜덤 액세스란?

랜덤 액세스는 데이터 블록을 순서대로 읽지 않고 여기저기 점프하면서 읽는 방식을 의미한다.

### 순차 접근

```text
1 → 2 → 3 → 4
```

연속된 위치를 읽기 때문에 효율적이다.

### 랜덤 액세스

```text
1 → 500 → 20 → 700
```

여러 위치로 이동하면서 읽기 때문에 비용이 커질 수 있다.

## 9. Selectivity와 Clustering Factor 차이

| 항목 | 의미 |
|---|---|
| Selectivity | 조건으로 얼마나 적은 데이터를 조회하는가 |
| Clustering Factor | 조회한 데이터가 테이블에 얼마나 모여 있는가 |

## 10. 옵티마이저 판단 흐름

옵티마이저는 대략 다음과 같이 판단한다.

```text
조건으로 적은 데이터가 조회되는가?
→ YES

조회 대상 데이터가 테이블에 잘 모여 있는가?
→ YES

인덱스 사용 가능성 증가
```

반대로 다음과 같은 경우에는 Full Table Scan을 선택할 수 있다.

```text
조회 건수가 많음
OR
랜덤 액세스가 많음
OR
통계 정보상 인덱스 비용이 더 큼
```

## 11. SQLP 시험 포인트

### Selectivity가 좋은 경우

- PK 조건
- Unique 컬럼 조건
- 중복이 적은 컬럼 조건
- 결과 건수가 매우 적은 조건

### Selectivity가 나쁜 경우

- 성별
- Y/N 컬럼
- 상태값
- 대부분의 데이터를 조회하는 조건

### Clustering Factor가 좋은 경우

- 테이블 저장 순서와 인덱스 순서가 비슷함
- 조회 데이터가 물리적으로 모여 있음
- 랜덤 액세스가 적음

### Clustering Factor가 나쁜 경우

- 테이블 저장 위치가 뒤섞여 있음
- 인덱스를 타도 테이블을 여기저기 읽어야 함
- 랜덤 액세스가 많음

## 12. PostgreSQL 실행계획과 연결

PostgreSQL에서 다음 명령어로 실행계획을 볼 수 있다.

```sql
EXPLAIN ANALYZE
SELECT *
FROM member
WHERE member_id = 'A123456';
```

실행계획에서는 다음과 같은 접근 방식이 나타날 수 있다.

- Seq Scan
- Index Scan
- Bitmap Heap Scan

옵티마이저는 다음 요소들을 고려해서 실행계획을 결정한다.

- Selectivity
- 통계 정보
- 인덱스 존재 여부
- 랜덤 액세스 비용
- 테이블 크기
- 조회 예상 건수

## 13. 핵심 요약

Selectivity는 얼마나 적게 조회되는가를 보는 개념이다.

Clustering Factor는 조회한 데이터가 얼마나 잘 모여 있는가를 보는 개념이다.

두 개념 모두 옵티마이저가 인덱스를 사용할지, Full Table Scan을 사용할지 판단할 때 중요한 기준이 된다.

## 14. 한 줄 암기

```text
Selectivity = 얼마나 적게 찾는가
Clustering Factor = 찾은 데이터가 얼마나 모여 있는가
```
