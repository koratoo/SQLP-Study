# 트랜잭션 수준 읽기 일관성 정리

## 1. 읽기 일관성이란?

데이터를 조회할 때  
중간에 다른 사용자가 데이터를 수정하더라도  
일관된 데이터를 읽는 성질을 의미한다.

---

## 2. 문장 수준 읽기 일관성

SQL 한 문장이 실행되는 동안에는  
같은 시점의 데이터를 읽는다.

예시:

```sql
SELECT * FROM member;
```

조회 중간에 다른 사용자가 데이터를 수정해도  
해당 SELECT는 시작 시점 기준으로 데이터를 읽는다.

---

## 3. 트랜잭션 수준 읽기 일관성

트랜잭션 전체가  
같은 시점의 데이터를 읽는 것을 의미한다.

예시:

```sql
BEGIN;

SELECT balance FROM account;

-- 다른 세션에서 데이터 수정 및 COMMIT

SELECT balance FROM account;

COMMIT;
```

트랜잭션 수준 읽기 일관성이 보장되면  
두 SELECT 결과가 동일하게 유지된다.

---

## 4. 기본 READ COMMITTED 특징

대부분 DBMS의 기본 격리수준은:

```text
READ COMMITTED
```

특징:

- SELECT 문마다 새로운 Snapshot 사용
- 문장 수준 읽기 일관성 보장
- 트랜잭션 전체 일관성은 보장하지 않음

즉:

```text
SELECT 할 때마다 새로운 사진을 찍는 개념
```

---

## 5. REPEATABLE READ 이상

격리수준을 높이면:

```sql
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

특징:

- 트랜잭션 시작 시점 Snapshot 유지
- 트랜잭션 내 모든 SELECT 결과 동일
- 트랜잭션 수준 읽기 일관성 보장

즉:

```text
처음 찍은 사진을 계속 사용하는 개념
```

---

## 6. 언제 사용하는가?

다음과 같은 경우 사용한다.

- 정산
- 통계
- 금융 처리
- 재고 처리
- 대용량 배치
- 쿠폰/포인트 중복 지급 방지

데이터 기준 시점이 흔들리면 안 되는 작업에서 중요하다.

---

## 핵심 요약

- 문장 수준 일관성
  → SQL 한 문장은 같은 시점 데이터 사용

- 트랜잭션 수준 일관성
  → 트랜잭션 전체가 같은 시점 데이터 사용
