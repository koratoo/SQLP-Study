# SGA가 필요한 이유와 구성요소

## 1. SGA란?

SGA는 **System Global Area**의 약자이다.  
오라클 데이터베이스 인스턴스가 사용하는 **공유 메모리 영역**이다.

여러 사용자가 데이터베이스에 접속하더라도, 공통으로 필요한 데이터와 실행 정보를 SGA에 올려두고 함께 사용한다.

---

## 2. SGA가 필요한 이유

SGA가 필요한 가장 큰 이유는 **디스크 접근을 줄이고 성능을 높이기 위해서**이다.

데이터베이스는 데이터를 디스크에 저장하지만, 디스크 접근은 메모리 접근보다 훨씬 느리다.  
따라서 자주 사용하는 데이터 블록, SQL 실행 정보, 변경된 데이터 등을 메모리에 올려두면 성능이 좋아진다.

SGA가 필요한 이유를 정리하면 다음과 같다.

- 자주 사용하는 데이터를 메모리에 저장해 디스크 I/O를 줄인다.
- 여러 사용자가 SQL과 데이터를 공유할 수 있게 한다.
- SQL 파싱 결과를 재사용해 하드 파싱을 줄인다.
- 변경된 데이터를 바로 디스크에 쓰지 않고 메모리에서 관리해 성능을 높인다.
- 트랜잭션 복구에 필요한 정보를 관리한다.

즉, SGA는 오라클이 빠르게 동작하기 위한 **공유 캐시 공간**이라고 볼 수 있다.

---

## 3. SGA의 주요 구성요소

## 3.1 Database Buffer Cache

데이터 파일에서 읽어온 **데이터 블록**을 저장하는 메모리 영역이다.

사용자가 테이블 데이터를 조회하면 오라클은 먼저 Buffer Cache에 해당 블록이 있는지 확인한다.  
있으면 메모리에서 바로 읽고, 없으면 디스크에서 읽어온다.

이 영역 덕분에 같은 데이터를 반복 조회할 때 디스크 I/O를 줄일 수 있다.

---

## 3.2 Shared Pool

SQL 실행과 관련된 정보를 저장하는 영역이다.

주요 내용은 다음과 같다.

- SQL 파싱 결과
- 실행 계획
- PL/SQL 코드
- 데이터 딕셔너리 정보

Shared Pool에 이미 파싱된 SQL 정보가 있으면 오라클은 이를 재사용할 수 있다.  
이것이 **소프트 파싱**이고, 재사용하지 못해 새로 파싱하는 것이 **하드 파싱**이다.

따라서 Shared Pool은 SQL 성능과 밀접한 관련이 있다.

---

## 3.3 Redo Log Buffer

데이터 변경 내역을 저장하는 메모리 영역이다.

INSERT, UPDATE, DELETE 같은 작업이 발생하면 변경 내용은 Redo Log Buffer에 먼저 기록된다.  
이후 LGWR 프로세스가 Redo Log File에 기록한다.

이 정보는 장애 발생 시 복구에 사용된다.

---

## 3.4 Large Pool

대용량 작업을 위한 선택적 메모리 영역이다.

주로 다음과 같은 작업에 사용된다.

- RMAN 백업 및 복구
- 병렬 처리
- 공유 서버 환경

Shared Pool의 부담을 줄이기 위해 사용된다.

---

## 3.5 Java Pool

오라클 내부에서 Java 기능을 사용할 때 필요한 메모리 영역이다.

일반적인 SQL 튜닝이나 SQLP 학습에서는 중요도가 상대적으로 낮다.

---

## 3.6 Streams Pool

Oracle Streams 기능에서 사용하는 메모리 영역이다.

데이터 복제나 메시지 처리와 관련이 있으며, 일반적인 SQL 성능 학습에서는 자주 다루지 않는다.

---

## 4. 핵심 요약

SGA는 오라클 인스턴스가 사용하는 공유 메모리 영역이다.

가장 중요한 역할은 다음과 같다.

- 데이터를 캐싱한다.
- SQL 실행 정보를 공유한다.
- 변경 이력을 관리한다.
- 디스크 I/O와 하드 파싱을 줄인다.
- 전체 데이터베이스 성능을 높인다.

SQLP 관점에서 특히 중요한 구성요소는 다음 세 가지이다.

1. Database Buffer Cache
2. Shared Pool
3. Redo Log Buffer

이 중 SQL 성능과 직접적으로 연결되는 것은 **Database Buffer Cache**와 **Shared Pool**이다.
