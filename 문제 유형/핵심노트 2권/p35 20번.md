# SQLP 문제 접근 방법 정리

## 문제 핵심

테이블의 PK 인덱스 컬럼 순서는 다음과 같다.

```sql
상품번호, 변경일시, 변경구분코드
```

즉 인덱스는 다음 순서로 정렬되어 있다고 볼 수 있다.

1. 상품번호
2. 변경일시
3. 변경구분코드

따라서 어떤 조건이 인덱스를 잘 활용하는지 판단하는 것이 핵심이다.

---

# 문제를 볼 때 생각해야 할 포인트

## 1. 최근 1년 조건

문제에서는 최근 1년 내 데이터만 조회한다.

```sql
변경일시 >= TRUNC(ADD_MONTHS(SYSDATE, -12))
```

이 조건은 변경일시에 대한 범위 조건이다.

즉 인덱스에서 다음과 같은 형태가 된다.

```text
상품번호 = 고정값
변경일시 >= 범위조건
```

---

# 2. 변경구분코드 조건의 위치

PK 컬럼 순서가 다음과 같기 때문이다.

```sql
상품번호 → 변경일시 → 변경구분코드
```

여기서 중요한 점은:

- 상품번호는 선두 컬럼이라 매우 잘 탐색 가능
- 변경일시는 두 번째 컬럼
- 변경구분코드는 세 번째 컬럼

따라서 변경일시에 범위 조건이 걸리는 순간:

```sql
변경일시 >= ...
```

그 뒤 컬럼인 변경구분코드는 인덱스 탐색 효율이 떨어질 수 있다.

즉 다음과 같은 상황을 생각해야 한다.

```sql
상품번호 = 'ZE367'
AND 변경일시 >= 최근1년
AND 변경구분코드 = 'C2'
```

이 경우 인덱스는:

1. 상품번호로 범위를 좁히고
2. 변경일시 범위를 탐색한 뒤
3. 그 안에서 변경구분코드를 추가 필터링

하는 형태가 될 가능성이 높다.

---

# 3. MAX() 사용 시 생각할 점

다음 형태는 흔히 등장한다.

```sql
SELECT MAX(변경일시)
```

하지만 MAX는 일반적으로:

- 조건에 맞는 후보를 찾고
- 그 중 최대값 계산

과정이 필요하다.

따라서 데이터 범위가 크면 비용이 커질 수 있다.

---

# 4. INDEX_DESC + ROWNUM 방식

다음 형태도 자주 등장한다.

```sql
INDEX_DESC
ROWNUM <= 1
```

이 방식은 보통:

```text
가장 최신 데이터부터 역순으로 읽다가
조건에 맞는 첫 건 발견 시 즉시 종료
```

전략이다.

즉:

- 전체 MAX 계산 없이
- 빠르게 한 건만 찾고 종료 가능

한 구조인지 생각해야 한다.

---

# 각 보기별로 생각해볼 포인트

## ①번

생각할 점:

```sql
서브쿼리에서 변경구분코드 = 'C2' 조건이 없음
```

즉:

- 최근 1년 내 최종 변경일시를 먼저 찾고
- 바깥에서 C2 여부를 확인

하는 구조다.

이 경우 정말 원하는 데이터가 맞는지 생각해봐야 한다.

---

## ②번

생각할 점:

```sql
서브쿼리 안에서도 변경구분코드 = 'C2'
```

즉:

- C2 데이터 중
- 최근 1년 내
- 가장 최신 변경일시

를 찾으려는 구조다.

다만 MAX 계산 비용도 함께 고려해야 한다.

---

## ③번

생각할 점:

```sql
단순 MAX(변경일시)
```

구조다.

가장 직관적이지만:

- 얼마나 많은 범위를 읽는가?
- 인덱스를 얼마나 효율적으로 사용하는가?

를 생각해야 한다.

---

## ④번

생각할 점:

```sql
INDEX_DESC
ROWNUM <= 1
```

즉:

- 최신 데이터부터 역순 탐색
- 조건 만족 시 즉시 종료

가능성이 있다.

여기서 핵심 질문은 이것이다.

```text
PK 인덱스 순서가
상품번호 → 변경일시 → 변경구분코드
일 때,

최신 변경일시부터 역순 탐색하면서
C2를 빠르게 찾을 수 있는가?
```

---

# SQLP 스타일 사고 방식

SQLP에서는 단순 문법보다 다음을 중요하게 본다.

- 인덱스 컬럼 순서
- 범위 조건 여부
- MAX 계산 비용
- 정렬 회피 가능 여부
- Stop Key 가능 여부
- 얼마나 빨리 탐색 종료 가능한가

즉 단순히:

```sql
조건이 많다 = 빠르다
```

가 아니라:

```text
인덱스를 어떤 방향으로 읽는가
언제 탐색을 멈출 수 있는가
```

를 보는 시험에 가깝다.

# SQLP 문제 핵심 질문 정답 정리

# 질문 1

## Q.

```sql
변경일시 >= 최근1년
```

이 조건은 인덱스에서:

- Equality 조건인가?
- Range 조건인가?

---

# 정답

```text
Range 조건이다.
```

---

# 이유

다음 조건을 보자.

```sql
변경일시 >= TRUNC(ADD_MONTHS(SYSDATE, -12))
```

이건 특정 값 하나를 찾는 것이 아니다.

예를 들면:

```text
2025-05-21 이상
```

처럼 범위를 조회한다.

즉 인덱스에서는:

```text
시작점부터 끝까지 스캔
```

해야 한다.

---

# Equality 조건과 비교

## Equality 조건

```sql
상품번호 = 'ZE367'
```

이건 정확히 하나의 위치를 찾는다.

즉:

```text
딱 한 지점 탐색
```

에 가깝다.

---

## Range 조건

```sql
변경일시 >= 특정일자
```

이건:

```text
특정 위치 이후를 계속 읽음
```

이다.

따라서 읽는 양이 늘어날 수 있다.

---

# SQLP 핵심 포인트

보통 인덱스에서는:

```text
Equality 조건까지는 매우 효율적
Range 조건부터는 스캔 범위 증가
```

라고 이해한다.

즉:

```sql
상품번호 = ?
AND 변경일시 >= ?
```

에서:

- 상품번호까지는 빠르게 탐색
- 변경일시부터는 범위 스캔

이 시작된다.

---

# 질문 2

## Q.

범위 조건 뒤의 컬럼인:

```sql
변경구분코드
```

는 인덱스 효율에 어떤 영향을 줄까?

---

# 정답

```text
범위 조건 이후 컬럼은
인덱스 탐색 효율이 크게 떨어질 수 있다.
```

---

# 이유

인덱스 순서를 다시 보자.

```sql
상품번호 → 변경일시 → 변경구분코드
```

그리고 조건은:

```sql
상품번호 = 'ZE367'
AND 변경일시 >= 최근1년
AND 변경구분코드 = 'C2'
```

이다.

여기서 중요한 점:

```text
변경일시 >= 최근1년
```

이 이미 Range Scan을 발생시킨다.

즉 인덱스는:

```text
상품번호는 정확히 탐색 가능
변경일시는 범위 탐색 시작
```

상태가 된다.

그러면 그 뒤 컬럼인:

```sql
변경구분코드
```

는:

```text
추가 필터
```

역할에 가까워진다.

---

# 쉽게 이해하기

예를 들면 인덱스가 이렇게 정렬되어 있다고 생각해보자.

```text
ZE367 | 2025-01-01 | A1
ZE367 | 2025-01-02 | B1
ZE367 | 2025-01-03 | C2
ZE367 | 2025-01-04 | D1
ZE367 | 2025-01-05 | C2
```

여기서:

```sql
변경일시 >= 2025-01-01
```

이면 여러 건을 읽어야 한다.

그 상태에서:

```sql
변경구분코드 = 'C2'
```

는 읽으면서 걸러내는 형태가 되기 쉽다.

즉:

```text
변경구분코드로 바로 점프 탐색이 어려움
```

이 핵심이다.

---

# SQLP 핵심 표현

시험에서는 자주 이렇게 표현한다.

```text
범위 조건 이후 컬럼은
Access 조건보다 Filter 조건으로 사용될 가능성이 높다.
```

---

# 질문 3

## Q.

다음 두 방식 중:

```sql
MAX()
```

과

```sql
INDEX_DESC + ROWNUM <= 1
```

어느 쪽이 더 빨리 종료 가능성이 높을까?

왜 그럴까?

---

# 정답

```text
INDEX_DESC + ROWNUM <= 1
```

방식이 빨리 종료될 가능성이 높다.

---

# 이유

## MAX() 방식

```sql
SELECT MAX(변경일시)
```

는 일반적으로:

```text
조건에 맞는 데이터들을 확인한 뒤
최댓값 계산
```

과정이 필요하다.

즉 범위를 어느 정도 읽어야 할 수 있다.

---

# INDEX_DESC 방식

```sql
INDEX_DESC
AND ROWNUM <= 1
```

는:

```text
최신 데이터부터 역순으로 읽음
```

전략이다.

즉:

1. 가장 최신 데이터 접근
2. 조건 만족 여부 확인
3. 만족하면 즉시 종료

가능성이 있다.

---

# 핵심 차이

## MAX()

```text
끝까지 계산하려는 성향
```

---

## INDEX_DESC + STOPKEY

```text
첫 건 찾으면 멈추려는 성향
```

---

# SQLP 핵심 키워드

이 문제에서 매우 중요한 개념:

```text
STOPKEY
```

이다.

대표 예시는:

```sql
ROWNUM <= 1
```

이다.

이 구조는:

```text
필요한 만큼만 읽고 종료
```

할 가능성이 있다.

---

INDEX_DESC + ROWNUM <= 1 은
